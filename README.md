# 기능상속 AI 에이전트

폐업한 생활 시설에서 하던 일을 인근의 어떤 시설이 이어받는지 매일 분석하여, 주민에게는 대체 시설을, 지자체에는 대응이 필요한 생활 공백을 알리는 AI 에이전트

- 2026년 AI 라이프 솔루션 챌린지 출품작 (대구광역시 실제 자료 기반)
- 웹 서비스: https://gineung.kr (지자체 화면 심사용 코드는 접속 화면에 안내)

## 1. 주요 기능

| 화면 | 이용자 | 주요 기능 |
|---|---|---|
| 주민 | 주민 | 폐업 시설 확인, 이용 목적 파악, 대체 시설·이동 경로(도보·버스) 안내, 생활 서비스(나드리콜 등) 연계 |
| 기능 공백 | 누구나 | 생활 필수 시설 도보권 부재 구역 공개, 창업 참고 정보 제공 |
| 지자체 | 담당 공무원 | 평일 자동 점검 보고(공백 심각도), 폐업 확인 요청, 폐업 사전 검토, 업무 보조 대화 |

## 2. AI 구성

| 구성 | 역할 |
|---|---|
| 생활 기능 분류 모델 | 시설·주민 요청을 생활 기능 113개(분야 17 → 이용 목적 39 → 생활 기능 113 → 세부 종류 424)로 분류 |
| 공백 판단 모델 | 폐업 시설별 보고 필요성 산정 (판단 요소 19개, 로지스틱 회귀, 평일 재학습) |
| 계산 엔진 | 100m 격자 인구·보행 도로망·버스 노선으로 도보 거리·영향 주민 수 산정 |
| 대화 엔진 | Claude(Anthropic) 기반. 주민 상담·지자체 업무 보조, 계산 엔진 수치만 사용하도록 자동 검증 |
| AI 에이전트 | 평일 오전 8시 30분 자료 수신 → 폐업 확정 → 기능 분류 → 공백 계산 → 심각도 판단 → 교차 검토 → 보고 |

## 3. 폴더 구성

| 폴더 | 내용 |
|---|---|
| `web/` | 웹 서버(`server.py`, 파이썬 표준 라이브러리)와 화면(`static/`) |
| `engine/` | 대체 시설 탐색, 대화 엔진(주민 `chat.py`·지자체 `gov_chat.py`), 지자체 에이전트(`gov_agent.py`), 공백 판단, 시험 묶음(`test_*.py`, `check5_cases.py`, `social_cases.py`) |
| `pipeline/` | 원자료 수집·가공, 매일 변화 반영, 폐업 공시 기준(`closure_policy.py`) |
| `design/` | 생활 기능 분류표(`purpose_taxonomy.json`), 등급표, 업종별 기능 연결표 |

## 5. 실행 방법

1. 파이썬 3.9 이상에서 도구 설치: `pip install -r requirements.txt`
2. `settings/` 폴더에 API 키 파일 준비 (Anthropic·카카오·브이월드·공공데이터포털 등, 저장소 미포함)
3. `pipeline/` 스크립트로 `data/` 자료 생성
4. 서버 실행: `python web/server.py 8000` → 브라우저에서 `http://localhost:8000`

## 6. 개인정보·보안

- 주민 상담 기록은 행정동·기능만 저장 (이름·연락처·위치 미수집)
- 카카오맵 검색·길찾기 결과는 안내 시 실시간 조회에만 활용, 저장하지 않음
- API 키는 서버 내부에서만 사용, 화면·저장소에 노출하지 않음
